## Purpose

評估結果的判定方式、8 個面向、報告格式與分數。第 2 階段輸出 JSON 報告(`npm run evaluate`),第 4 階段加上 HTML 報告與各面向 0~100 分。來源:`docs/spec/03` 判定、面向與改進方向、報告格式,`04` Lighthouse 式結構與評分。

## ADDED Requirements

### Requirement: 判定方式

每個項目 SHALL 在每種測試寬度各判一次,取最差的結果。任一項不合格,該範本或頁面即不合格;警告累計達門檻(預設 3 項,可設定)也視同不合格。

#### Scenario: 三個警告

- **WHEN** 某範本有 3 項警告、0 項不合格
- **THEN** 該範本判定為不合格

### Requirement: 八個面向

每個項目 SHALL 歸屬一個面向,報告依面向彙整:

| 面向 | 涵蓋的項目 | 改進方向 |
| --- | --- | --- |
| 比例 | 圖片比例 | 後端依主比例裁圖 |
| 對齊 | 同列對齊、欄寬照格線、欄底對齊、欄高 | 統一文字量、限制標題行數,或換不怕高度差的型(如 09) |
| 完整 | 末列不落單 | 則數調成欄數的倍數,或改欄數 |
| 密度 | 區塊長度、區塊數、整頁則數、用途則數、填充率 | 改輪播、加「看更多」、減則數 |
| 節奏 | 間距節奏、同型不連續、列距 | 換相鄰區塊的型、統一間距 |
| 層級 | 手機首屏、單塊不重複、放大型不相鄰 | 頭條改型 02、減少放大型 |
| 文字 | 標題行數 | 限字數、加寬欄、降低文字量 |
| 可用性 | 觸控目標、水平捲動 | 觸控 ≥ 44px、移除固定最小寬度 |

#### Scenario: 末列落單的面向

- **WHEN** 「末列不落單」不合格
- **THEN** 報告把它列在「完整」面向

### Requirement: 報告內容

報告 SHALL 每頁、每種寬度一份,手機與電腦並列對照。每一行 SHALL 包含:量到的數字、判定、所屬面向、改進建議。JSON 報告另外包含分數、違規項目與候選改法,供 AI skill 讀取。

#### Scenario: 一行報告

- **WHEN** 首頁 390px 的版位 F 估算為 2.3 屏
- **THEN** 報告寫出「2.3 屏、超過上限 2 屏、不合格、屬密度」,並附建議(例如改成輪播或減到 4 則)

### Requirement: 分數

報告 SHALL 給 8 個面向各 0~100 分與加權總分。分數由違規依嚴重度加權計算,權重可設定,先依經驗訂,上線後以數據校正。評分 MUST 是確定性的。

#### Scenario: 沒有違規

- **WHEN** 某頁沒有任何警告或不合格
- **THEN** 8 個面向都是 100 分

### Requirement: 報告指令

系統 SHALL 提供 `npm run evaluate` 輸出 JSON 報告(第 2 階段),第 4 階段再加上 HTML 報告。

#### Scenario: 輸出 JSON

- **WHEN** 執行 `npm run evaluate`
- **THEN** 產生一份 JSON 報告,含每頁每種寬度的項目結果
