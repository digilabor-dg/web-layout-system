# POC 3:參數產生版型 + 表單

**參數(表單)→ JSON → 產生版型 → 評分與回饋 → 改參數 → 再跑。**

```bash
npm run poc:generate -- poc/generator/params/default.json
```

```bash
npm run poc:generate -- --all
```

```bash
npm run poc:generate -- poc/generator/params/default.json --json-only
```

- `--all`:依序跑 `params/` 底下全部參數,並寫出 `results/summary.json`。
- `--json-only`:只跑 JSON 估算,不開瀏覽器。
- **表單**:用瀏覽器開啟 `form.html`,填完下載 JSON,存到 `params/` 後執行上面的指令。

## 參數

格式見 `params.schema.json`。

| 欄位 | 說明 |
| --- | --- |
| `blocks` | 要放的區塊,依閱讀順序(頭條、次頭條、快訊、熱門、影音、5 個分類、專題、觀點、短影音) |
| `sidebar` | 放在側欄的區塊 |
| `fullWidth` | 獨佔一整列的區塊 |
| `columns` | 主欄:側欄,例如 `[8, 4]` |
| `preset` | `bs5`、`tw4`、`md3` |
| `strategy` | `greedy`(逐塊改良)或 `beam`(集束搜尋,`beamWidth` 預設 3) |

## 產生器怎麼挑

1. **組 section**:全寬的區塊獨立成 flow;其餘依序放進 stack 的主欄或側欄。
2. **每塊的合法選項**:
   - 展示類型只用該內容類型的建議搭配(而且 POC 渲染器支援的)。
   - 則數同時受展示類型與用途的範圍限制。
   - 另外可選電腦欄數、輪播一次顯示幾張、要不要縮圖。
   - 每種區塊有 2~26 個選項。
3. **分配新聞**:有分類的區塊先拿,泛用的(頭條、次頭條、熱門)最後拿剩下的;同一頁不重複,不夠分的組合直接淘汰。
4. **目標函數**:
   - 以 POC 2 的 JSON 估算總分為主。
   - 同分時,有問題的對象越少越好。
   - 再扣掉欄高與欄底的差距百分比,讓搜尋往平衡的方向走。
   - 第 1 層有錯誤的組合為 −∞。
5. **搜尋**:
   - `greedy`:從預設值開始,逐塊試所有選項、取最好的;整頁重複到沒有改善(最多 4 輪)。
   - `beam`:逐塊展開,每一步保留最好的 k 種。
6. **最後用完整評估**(含渲染量測)產生報表。

## 結果

| 參數 | 試算組合 | 完整評估總分 |
| --- | --- | --- |
| `default`(bs5、貪婪法) | 406 | 90 |
| `tw4-beam`(Tailwind 4、集束搜尋) | 416 | 90 |
| `no-sidebar`(Material 3、無側欄) | 349 | 96 |
| `from-form`(表單產生) | 368 | 90 |

手排的範例首頁是 74 分。每組的產出在 `results/<名稱>/`:`generated.json`(參數、每塊的選擇、搜尋紀錄、頁面、範本、實例)、`report.json`、`report.html`、`screenshots/`。

## ⚠️ 已知問題:評估器的漏洞會被搜尋利用

`no-sidebar` 拿到 96 分,但版面明顯不好:整頁高 11,640px,觀點評論的 4 張方圖每張寬 1264px。原因是規格的「區塊長度」只檢查手機,電腦版沒有任何項目限制區塊或圖片的大小。**只要評分有缺口,搜尋就會鑽進去。**

另外,產生器偏好 P07 均分圖卡:格線沒有欄底對齊、填充率這類問題,評分上最「安全」,但版面會變單調。評估目前沒有任何項目獎勵版面的變化與層次。

這兩點都列在 `docs/wiki/待確認.md`,需要決定要不要新增評估項目。
