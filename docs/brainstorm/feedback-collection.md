# 反饋收集

> **狀態:試驗中。**第 1~3 節(圈選、方向型量表)的 MVP 已做在檢視工具的「圈選」模式(`poc/rating/review.html`,判定在 `poc/rating/region.ts`);其他各節仍是發想。2026-11-03 與使用者討論後整理。還不是規格;決定要做時,開 OpenSpec change(暫名 `score-calibration`),條文以 `openspec/specs/` 為準。
>
> 背景與現有工具見 [人評對齊](../wiki/人評對齊.md):目前的檢視工具 `poc/rating/review.html` 是「點選區塊、給 0~10 分、寫短評」,外加 A/B 比較。

## 目標

人很難說出版面哪裡有問題,但看得出、比得出好壞。這份發想要讓反饋**好給、好量化、能直接變成參數**:

- **好給**:圈一塊區域就能評,不用知道它是哪個區塊。
- **好量化**:每則反饋都變成「目標 + 軸 + 值」。
- **能變成參數**:每條軸都對到評估器量得到的數字,以及產生器可以調的參數。

## 1. 圈選區域

使用者在預覽頁面上任意畫一個區域,不必剛好框住區塊或物件,也可以是空白。

程式依渲染後每個元素的位置計算目標。這是確定性的:同一個圈選,永遠得到同樣的結果。

1. **圈到東西**:計算圈選區和區塊、單則、元素(圖、標題、名次)的重疊。重疊最多、而且佔圈選面積一半以上的,就是目標。
2. **圈到空白**:找出包住它的最小框,判斷是哪一種空白,再找上下左右最近的元素當鄰居。
   - 空白在區塊裡 → 區塊內的留白,例如末列缺格、填充率。
   - 空白在欄裡、區塊外 → 欄底留白,也就是欄高不平衡。
   - 空白在兩塊之間 → 間距。
3. **跨好幾塊**:列出多個目標,依重疊比例加權。通常是在講兩塊之間的關係,例如輕重、相鄰。

### 範例(示意首頁的產生結果 `default`,電腦版 1280px)

| # | 圈哪裡 | 程式判定的目標 | 評價 | 對到 |
| --- | --- | --- | --- | --- |
| 1 | K 觀點評論那一長條 | K(重疊 100%) | 大小 +4 | 新項目候選「區塊長度(電腦)」;參數:作者卡改小頭像,或改兩欄 |
| 2 | B 焦點新聞右邊空著的第 4 格 | 空白,在 B 裡面;鄰居是 B 的第 3 則 | 數量 −3 | 現有的「末列不落單」;參數:則數 3 → 4,或改 3 欄 |
| 3 | 1024px 時,K 下方的大片空白 | 空白,在右欄、區塊外;鄰居是上方的 K、左邊的 H | 留白 −4(太空) | 現有的「欄高」;參數:右欄加一塊,或從左欄移一塊過去 |
| 4 | D 熱門排行的名次和縮圖之間 | D 的名次與縮圖兩個元素 | 位置:太遠 | 渲染器的樣式,不是評估項目 |
| 5 | 橫跨 A 頭條下緣和 B 焦點 | A 55%、B 45% | 層級:A −2(太弱) | 兩塊的輕重;接近現有的「放大型不相鄰」 |
| 6 | A 頭條的疊字標題 | A 的疊字元素 | 對比 −3(太淡) | 新項目候選「疊字對比」 |
| 7 | 手機版 E 影音焦點 | E | 內容類型:想看文字新聞 | 選項,不是分數;只記錄偏好 |

## 2. 評分尺度

−5~+5 有兩種用法,要分開:

| 尺度 | 0 代表 | 和 0~10 的關係 |
| --- | --- | --- |
| **喜好**:不喜歡 ↔ 喜歡 | 中性 | 一樣,分數加 5 就是 0~10 |
| **方向**:太小 ↔ 太大 | 剛好 | 不一樣,−5 和 +5 都不好 |

方向型比 0~10 多兩個好處:

- **說得出往哪邊改**:「大小 +3」就是圖要改小,「數量 −2」就是要加則數。
- **看得出意見是否分歧**:分得出「大家都說太大」和「一半說太大、一半說太小」,後者不該改。

介面上用兩端標好說法的滑桿,0 在中間;程度就是離 0 多遠。例如:

```
圖多一點  ●───●───●───●───●───◆───●───●───●───●───●  字多一點
太空      ●───●───●───●───●───◆───●───●───●───●───●  太擠
```

## 3. 維度

每條軸都要對到一個量得出來的數字,和一組可以調的參數:

| 軸 | −5 | +5 | 程式量的數字 | 可以調的參數 |
| --- | --- | --- | --- | --- |
| 數量 | 太少 | 太多 | 則數 | 則數 |
| 大小 | 太小 | 太大 | 區塊高 ÷ 視窗高、單張圖寬 | 欄數、圖片角色 |
| 圖 ↔ 字 | 圖多一點 | 字多一點 | 圖片面積 ÷(圖片 + 文字面積) | 圖片角色、縮圖比例、文字量 |
| 空 ↔ 擠 | 太空 | 太擠 | 留白面積 ÷ 區塊面積、每屏則數 | 則數、欄數、間距 |
| 層級 | 太弱 | 太搶 | 區塊面積、標題字級(相對於鄰居) | 展示類型的強調 |
| 位置 | 該往前 | 該往後 | 區塊順序 | 區塊順序、所在的欄 |
| 色彩、對比 | 太淡 | 太重 | 文字與背景的對比 | 網站設定 |
| 內容類型 | (選項) | | | 範本的內容類型 |
| 整體 | 不喜歡 | 喜歡 | (就是現在的 0~10) | |

**兩條軸分開,才分得出原因。**「太空」常常是「圖太多、字太少」造成的:

- 左圖右文清單:縮圖高、標題只有一行,文字旁邊空 → 同時是「字多一點」和「太空」。改法是縮小縮圖或加摘要。
- 格線最後一列缺兩格 → 只有「太空」,圖文比正常。改法是調則數或欄數。

色彩目前只能評疊字對比,因為渲染器用的是灰色佔位圖。

### 維度目錄

維度會越來越多(例如 100 個),所以做成一份目錄(JSON),格式和評估項目一樣固定,並排成一棵樹:

| 欄位 | 例子 |
| --- | --- |
| 兩端的說法 | 太空 ↔ 太擠 |
| 適用條件 | 區域裡有文字,而且是清單型 |
| 量法 | 留白面積 ÷ 區塊面積 |
| 剛好的範圍 | 先用猜的,之後由評價資料擬合(見第 8 節) |
| 對到的參數 | 縮圖比例、文字量 |
| 下一層 | 太空 → 縮圖太大、字太少、列距太大、末列缺格 |

```
密度
├─ 太空
│  ├─ 縮圖太大      → 縮圖比例
│  ├─ 字太少        → 文字量
│  ├─ 列距太大      → 間距
│  └─ 末列缺格      → 則數、欄數
└─ 太擠
   └─ …
```

## 4. 從短評萃取

軸、方向與程度,也可以從使用者寫的短評中萃取出來,由 skill(AI)負責。一句短評可以拆出好幾筆,裝置與位置也一起抽出來。

以第二輪角色的短評為例:

| 區塊 | 短評 | 萃取 |
| --- | --- | --- |
| D 熱門排行 | 排行配大方圖太佔高度,編號與標題之間隔太開,一眼掃不完前五名 | 圖 ↔ 字 +3(字多一點)、大小 +3、名次與縮圖之間 空 ↔ 擠 −2 |
| K 觀點評論 | 手機 2 欄桌機反變 1 欄,方圖撐到近 400px 高,作者卡長到失控 | 電腦版 大小 +5;另記一個非軸的問題「電腦欄數比手機少」 |
| B 焦點新聞 | 手機第三張卡落單,右邊空一塊;電腦版三張卡排完,右側也空著一截 | 手機 右邊 空 ↔ 擠 −2;電腦 右側 空 ↔ 擠 −2 |
| C 即時 | 純文字一行一則,掃得最快 | 喜好 +4(稱讚也要收,這是「剛好」的證據) |
| 年長讀者的整體意見 | 灰色小字對年長讀者太小 | 字級 −3:不在目錄裡,成為**新維度的候選** |

```json
[
  { "axis": "圖↔字", "value": 3, "evidence": "大方圖太佔高度" },
  { "axis": "大小", "value": 3, "evidence": "太佔高度" },
  { "axis": "空↔擠", "value": -2, "target": "名次與縮圖之間", "evidence": "隔太開" }
]
```

程度用一張固定的詞表,讓每次萃取的標準一致:

| 用詞 | 程度 |
| --- | --- |
| 有點、偏、稍微 | 1~2 |
| 太、很、大片 | 3 |
| 超、極、一大塊、失控 | 4~5 |
| 不算、還好(否定) | 該軸記 0,或不記 |

**這不違反「評分必須是確定性的程式」**:萃取的角色是資料輸入,和人填分數一樣。

1. AI 萃取一次,結果存成 JSON 檔,不會每次重跑。
2. 程式檢查萃取結果,這些檢查都是確定性的:
   - `evidence` 必須是原文裡真的有的字。
   - 方向要和量到的數字一致。例如短評說「太空」,但量到的留白很少,就標出來給人看。
3. 之後的統計與擬合,全部是確定性的程式。
4. 抽樣給人核對,算出 AI 萃取和人工判讀的一致率。

## 5. 猜他想說什麼

維度很多時,在使用者圈下區域的當下,挑出他最可能想說的 3~5 個,讓他確認:

```
┌─ 你想說的是?──────────────────────┐
│ ① 文字旁邊太空            ●●●○○  │ ← 預填程度,可以拖
│ ② 縮圖太大、字太少        ●●○○○  │
│ ③ 標題太短,想看摘要                │
│ ④ 和上一塊(政治)太像               │
│ ── 都不是,我自己說 ─────────────── │
└────────────────────────────────────┘
```

全程都是確定性的程式,不需要 AI:

1. **算目標與特徵**:例如圈到 J 社會右邊,區域裡 72% 是空白,J 的填充率 38%,和 G 同一型。
2. **篩出適用的維度**:依目錄的適用條件,例如「疊字對比」只適用於疊字型。100 個先篩到大約 15 個。
3. **排序**:兩個分數相乘。
   - **偏差**:量到的數字離「剛好」有多遠。
   - **歷史確認率**:過去在同類情況下(同型、同裝置、同一種空白),大家最常確認哪一個。
4. **預填程度**:依偏差大小先填好,使用者自己調。

一開始沒有歷史資料時,只靠偏差和評估器已經抓到的問題來排序。

## 6. 適應性提問:先問 3 題,再依回答問下 3 題

和電腦化適性測驗同一個原理:每一輪都依前一輪的回答,挑最能縮小範圍的下一組題目。

**範例**:圈了 J 社會右邊的空白。

| 輪 | 題目 | 回答 |
| --- | --- | --- |
| 1 | 這裡太空還是太擠? | 太空(−3) |
| 1 | 圖和字的比例? | 字多一點(+2) |
| 1 | 和周圍比,這塊太搶還是太弱? | 剛好(0) |
| 2 | 縮圖太大嗎? | 太大(+2) |
| 2 | 想看到摘要嗎? | 想 |
| 2 | 列與列之間太開嗎? | 剛好(0) |

結果:縮小縮圖、加上摘要。接著接第 7 節,當場給他看改完的樣子。

**挑題規則**(同樣的回答,永遠得到同樣的下一題):

1. 答 0:剪掉這一支,不再追問。
2. 答了方向:展開它在目錄樹底下的原因。
3. 同一輪的 3 題要分散在不同支。
4. 候選很多時,先問最能把候選分成兩半的題目。
5. 可以答「不知道」:當成沒回答,不當成 0。

**什麼時候停**:走到對得到參數的那一層,或最多 3 輪(9 題),或使用者說「就這樣」。

## 7. 「這樣會不會更好?」

直接給幾個改法讓他挑,連「哪裡有問題」都不用說出口。就像驗光師問「1 比較清楚,還是 2 比較清楚?」,一路比下去就收斂。

**範例**:圈了 J 社會。

| 輪 | 選項 | 他選 |
| --- | --- | --- |
| 1 | 原樣 / 縮圖改小(佔寬 1/4 → 1/5)/ 加摘要 / 改成格線 3 欄 | 加摘要 |
| 2 | 加摘要 / 加摘要 + 縮圖改小 / 加摘要但只留一行 | 加摘要 + 縮圖改小 |
| 3 | 在上一輪的選擇附近再細分 | 選回上一輪的選擇 → 收斂,停止 |

每個改法對應的參數與數字變化都是已知的,所以軸、方向與程度都能由程式反推回來,使用者不需要會講這些詞。

**規則**:

1. **一個選項只改一件事**,否則不知道他喜歡的是哪個改變。範例 07 的 V1、V2 混了兩個變因,8 個角色的 A/B 結果就沒辦法解讀。
2. **一定要有「原樣」**,並打亂位置。他選原樣,代表這裡其實沒問題,或這幾個改法都不對。
3. **要在上下文裡看**:至少顯示相鄰的區塊,因為改一塊可能讓欄高失衡。
4. **程式分數先藏起來**:選完才揭曉。每一次挑選都順便產生一筆 A/B 一致率的資料。
5. **選項要分散**:同一輪的改法要往不同方向,例如改圖、改字、換型。

**選項從哪裡來**:第 5 階段「改進建議」的流程。候選改法(單一參數)→ 公式試算、刪掉會產生新問題的 → 依偏差與歷史排序 → 挑方向不同的前 3 名 → 只渲染這 3 個。差別只在最後由人來選,也就是「人在迴圈裡的貪婪法」。

收斂到的改法,可以回存成產生器的參數預設值。

## 8. 從評價找出「剛好」的位置

每則評價都配著當時量到的數字。收得夠多以後,看評價在哪個數字從負變成正,那裡就是大家覺得剛好的地方。

**虛構的數字**,只為說明做法。假設收到的左圖右文清單評價是:

| 留白比例 | 平均評價(太空 ↔ 太擠) |
| --- | --- |
| 70% | −3 |
| 50% | −1 |
| 35% | 0 |
| 20% | +2 |

這類區塊的「剛好」大約是留白 35%,可以直接當評估器的門檻,取代規格裡猜的值。

- 剛好的位置要**依展示類型分開算**:輪播本來就該圖多,純文字清單本來就沒有圖。
- 第 7 節的挑選是「同一處、只差一個參數」的偏好比較,數字差異已知,擬合起來比單純打分數精準。
- 擬合是程式算的,一樣是確定性的:同樣的資料得到同樣的門檻。

## 9. 三種方式混著用

| 使用者的狀態 | 用哪種 |
| --- | --- |
| 說得出問題 | 自由短評,由 skill 萃取(第 4 節) |
| 知道大方向 | 適應性提問(第 6 節) |
| 說不出來,但看得出好壞 | 「這樣會不會更好」的選項(第 7 節) |

一個好用的組合:先讓他自由寫一句(選填),再問一題大方向;答「不知道」,就直接改給選項。

```
圈選 → 自由短評(選填)→ 第 1 輪 3 題 → 第 2 輪 3 題 → 產生改法 → 當場 A/B
          ↓                       ↓                          ↓
     skill 萃取軸          記錄路徑與回答            確認改法有沒有效
```

## 10. 資料格式

所有方式最後都存成同一種「目標 + 軸 + 值」,可以合併統計:

| 輸入方式 | 位置從哪來 | 軸與程度從哪來 |
| --- | --- | --- |
| 圈選 + 滑桿 | 圈選的區域 | 滑桿 |
| 圈選 + 短評 | 圈選的區域 | 從短評萃取 |
| 只有短評 | 短評裡的區塊、裝置、位置用詞 | 從短評萃取 |
| 「這樣會不會更好」 | 圈選的區域 | 由選中的改法反推 |

```json
{
  "width": 1024,
  "mode": "blind",
  "region": { "x": 700, "y": 2380, "w": 300, "h": 700 },
  "targets": [
    { "ref": "section s3 右欄", "kind": "blank", "overlap": 1.0, "adjacent": ["inst-gen-opinion", "inst-gen-finance"] }
  ],
  "ratings": { "空↔擠": -4 },
  "comment": "右欄下面空一大塊"
}
```

圈選區和程式判定的目標都存下來。版面改了以後,可以用穩定的 `ref` 重新對應。

## 11. 要注意:建議會引導答案

先給選項或題目,人容易順著選,收回來的資料就會像程式自己的想法,失去校正的意義。

| 模式 | 顯示建議與題目 | 用途 |
| --- | --- | --- |
| 盲評 | 不顯示,自己打字或拉滑桿 | 校正評估器、擬合「剛好」 |
| 快速 | 顯示 | 大量收集、日常使用 |

- 每筆資料都記下是哪種模式。比較兩種模式的分布,就知道建議造成多少偏差。
- 結構化的題目之前,先讓他自由寫一句。
- 每一輪都留「其他,我自己說」。

## 12. 怎麼知道做得好不好

每一輪都追蹤,和 A/B 一致率、覆蓋率一起看:

| 指標 | 意思 |
| --- | --- |
| 前 3 名命中率 | 使用者要的,有沒有在建議的前 3 名 |
| 「都不是」的比例 | 維度目錄還缺多少 |
| 預填程度被改了多少 | 偏差換算成程度準不準 |
| 萃取一致率 | AI 萃取和人工判讀相同的比例 |
| 收斂輪數 | 「這樣會不會更好」平均幾輪收斂 |

回答的路徑本身也是資料:常走的路徑可以提前問,總是答 0 的題目往後排,常選「其他」的地方,就是目錄樹缺的那一支。

## 13. 已有的理論與方法

這些做法大多屬於 UX 研究、感官評估與心理測量,都有成熟的理論與實作。**我們應該沿用既有的名稱與做法,不要自己重新發明。**

| 我們的做法 | 既有的方法 | 領域 | 可以借用的 |
| --- | --- | --- | --- |
| 太少 ↔ 剛好 ↔ 太多 | JAR(Just-About-Right)量表 | 感官評估(食品、消費品) | **懲罰分析**:某一軸不在「剛好」時,整體喜好掉多少,用來決定先改哪一軸 |
| 兩端標好說法的軸 | 語意差異量表(Osgood);UX 版的 AttrakDiff、UEQ | 心理測量、UX | 成對形容詞的設計方式,以及信度、效度的檢驗 |
| 從使用者的詞彙找到設計參數 | 感性工學(長町三生) | 工業設計 | 收集感性詞彙 → 評分 → 統計出「哪個設計要素影響哪種感覺」 |
| 圈選區域對到元素 | 眼動研究的 AOI(興趣區) | HCI | AOI 的劃定與重疊規則 |
| 先問 3 題、再問 3 題 | 電腦化適性測驗(CAT)、項目反應理論(IRT) | 心理測量 | 選題規則、停止規則 |
| 這樣會不會更好 | 驗光師演算法、偏好式貝氏最佳化、Sequential Line Search、互動式演化計算 | HCI、最佳化 | 人在迴圈裡調參數、少量比較就收斂的方法 |
| A/B、兩兩比較 | A/B 測試、Bradley–Terry 模型 | 統計、產品 | 從兩兩比較推出排序與強度 |
| 專家角色逐項檢查 | 啟發式評估(Nielsen 十大原則)、認知走查 | UX | 檢查清單與嚴重度分級 |
| 第一眼的印象 | 五秒測試、網頁第一印象研究 | UX | 第一印象只要極短時間就形成,可以單獨評 |
| 專家角色與讀者角色分開 | 描述型分析(受訓評估員)與喜好測試(一般消費者) | 感官評估 | 受訓評估員只描述各軸的強度、不評喜好 |
| 重評的分數變動 ±0.5 | 再測信度、評分者間一致性(Krippendorff's α、ICC) | 心理測量 | 一致性的標準算法與可接受的門檻 |
| 評估器的量法 | 計算美學(平衡、對稱等版面指標)、視覺雜亂度、視覺顯著性預測、網站美感的大規模群眾評分 | HCI | 可以參考的量法與公開資料集 |

**我們的不同之處不在單一方法**,而在把它們接成一個迴圈:

1. 評估器逐元素量出數字,而且是確定性的。
2. 每條軸都對到產生器的參數。
3. 先用 AI 角色篩出盲點,再請真人確認。
4. 收斂的結果回存成評估器的門檻與產生器的預設值。

寫成正式規格之前,先做一次文獻整理,確認名稱、作者與年份,並挑出可以直接採用的量表與分析方法。
