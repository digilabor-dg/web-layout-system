# 評估工具

評估工具採兩段式,像 Google Lighthouse 一樣產生分數與改進建議:核心用 Node.js 量測與評分,AI skill 負責解讀與建議。目前是規格,尚未實作。

## 兩段式評估

| 階段 | 輸入 | 類似工具 | 能判定的項目 |
| --- | --- | --- | --- |
| JSON 評估 | 範本、實例、新聞則的 JSON | 程式碼檢查器(如 ESLint) | 規則檢查全部;末列不落單、同型不連續、區塊數、整頁則數、單塊不重複;估算欄底對齊、區塊長度、手機首屏、標題行數、間距節奏 |
| 渲染評估 | 實際頁面,6 種測試寬度 | Lighthouse | 圖片顯示比例、同列對齊、欄寬照格線、觸控目標、水平捲動,並驗證 JSON 的估算值 |

JSON 評估快,存檔時就跑;渲染評估慢但準,用於最後驗收。

## 對應 Lighthouse 的結構

| Lighthouse | 本工具 |
| --- | --- |
| 收集器(gatherer) | 量測腳本:欄位高度、圖片比例、區塊位置 |
| 稽核(audit) | 驗收標準的各項,判定合格、警告、不合格 |
| 類別分數 | 8 個面向各 0\~100 分,加權成總分 |
| 改善機會(附預估效益) | 改法建議,附改完後的預估分數 |
| 行動版 / 桌面版模式 | 6 種測試寬度 |

建議自己用 Playwright 寫 Lighthouse 風格的工具,不塞進 Lighthouse 本身;但真的 Lighthouse 仍一起跑,覆蓋載入效能與對比度、替代文字等無障礙檢查。它的版面位移(CLS)指標與圖片比例規範相關:圖片框預留正確比例,CLS 自然就好。

## 工具分工

| 工作 | 交給 | 原因 |
| --- | --- | --- |
| JSON 規則檢查 | Node.js | 同樣輸入必須得到同樣結果 |
| 渲染量測 | Node.js | Playwright 與 Lighthouse 都是 Node.js 工具 |
| 評分、高度估算、候選改法 | Node.js | 都是公式,用程式算又快又準 |
| 判斷不平衡是否刻意 | AI skill | 需要理解編輯意圖 |
| 判讀圖內文字、海報式圖卡 | AI skill | 要看圖,程式偵測不到 |
| 寫成人看得懂的報告 | AI skill | 把數字翻成「改哪裡、為什麼」 |
| 依建議修改範本 JSON | AI skill | 改完再呼叫 Node.js 重新評分 |

只用 AI 不行:每次結果可能不同,分數無法重現,試算上千種改法也太慢太貴。只用 Node.js 也不行:它只能照規則判斷,會把編輯刻意的不平衡誤判為不合格。

1. Node.js 工具輸出 JSON 報告:分數、違規項目、候選改法。
2. AI skill 讀報告、看截圖,判斷哪些違規真的要改。
3. AI skill 寫出建議,經人確認後修改範本。
4. 再跑一次 Node.js 工具驗證。

## 改進建議的產生

工具不只說哪裡不合格,還列出「改成怎樣會合格」。

**候選改法**:則數在展示類型範圍內加減、換同用途分組的型、改欄數、主欄與側欄互換位置。超出則數範圍、改主比例不列入;跨用途分組換型由人決定。

**高度估算公式**:

- 卡片寬 = (容器寬 − 欄距 × (欄數 − 1)) ÷ 欄數
- 圖片高 = 卡片寬 ÷ 主比例(3:2 即 ÷ 1.5)
- 卡片高 = 圖片高 + 標題行數 × 行高 + 內距
- 區塊高 = 列數 × 卡片高 + (列數 − 1) × 列間距

例:容器 1200px、3 欄、欄距 16px,卡片寬約 389px,3:2 圖高約 259px。

**評分**:各項違規依嚴重度加權成違規分數,越低越好;權重先依經驗訂,上線後用數據校正。

1. 跑完三層檢查,列出所有不合格與警告。
2. 為每項違規列出合法的候選改法。
3. 用公式估算每個改法的分數,不必渲染,可試上千種。
4. 只拿分數最低的前 3 個實際渲染驗證。
5. 輸出建議:改哪裡、改成什麼、改完預估分數。

多處同時調整時,用貪婪法:每次只改最有效的一處,重複到沒有改善為止。

## 需要的知識

| 知識 | 負責什麼 |
| --- | --- |
| 版面設計理論 | 定義平衡:格線、視覺重量、層級、留白節奏 |
| 新聞編輯判斷 | 分辨不平衡是否刻意,例如 8:4 的主欄與側欄 |
| 前端量測技術 | 用無頭瀏覽器在 6 種寬度渲染並量測 |
| 量化指標設計 | 把感覺變成數字,訂一般標準與上限 |
| 使用者行為數據 | 用數據驗證門檻,而不只是專業意見 |

前三項由前端工程師與設計師即可完成;後兩項需要有人負責訂指標與上線後的數據追蹤。

數學上只需要算術與餘數、矩形的平面幾何(長寬、面積、比例)、加權評分與貪婪法;不需要微積分與三角函數,因為版面都是水平垂直的矩形,要調的也是「幾則」「哪一型」這種離散選擇。圖內文字與視覺重量的偵測底層是影像處理,用現成函式庫即可。

## 上線後驗證

- 追蹤捲動深度、點擊熱圖與各區塊點擊率。
- 用 A/B 測試比較兩種版面,校正門檻與權重。
- 這部分需要統計:平均數、變異與顯著性檢定。

## 版面生成(第 7 階段)

評估系統完成後才做:評估分數就是生成時判斷好壞的依據。

- **目標**:從空白開始,逐塊推薦下一個合適的區塊,自動排出合格的版面。
- **第一步 貪婪法**:每一步選當下分數最高的下一塊,適合單頁、規則簡單。
- **第二步 集束搜尋**:每一步保留前 k 種排法繼續往下長,首頁十幾個版位用這個即可。
- **進階 仿生演算法**:黏菌、蟻群、基因演算法等,大量探索並強化高分排法;只在為大量客戶網站自動產生版面,或依讀者即時個人化時才需要。
- **限制**:生成結果仍要通過三層檢查,並由人確認後才上線。
