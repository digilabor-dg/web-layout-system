# 估算與渲染

> 白話說明 [`height-estimation`](../../openspec/specs/height-estimation/spec.md)、[`html-rendering`](../../openspec/specs/html-rendering/spec.md)、[`render-measurement`](../../openspec/specs/render-measurement/spec.md)。條文以 spec 為準。
>
> 狀態:🧪 POC 1([`poc/estimate-vs-render/`](../../poc/estimate-vs-render/README.md))已驗證;正式版是第 2~4 階段。

評估要知道每塊有多高。有兩種方法:**估算**(只看 JSON,很快,可以一次試上千種改法)與**渲染量測**(真的在瀏覽器排出來量,慢但準)。估算拿來試算,量測拿來驗收和校正估算。

## 高度估算:不開瀏覽器,用公式算

```
卡片寬 = (內容寬 − 欄距 × (欄數 − 1)) ÷ 欄數
圖片高 = 卡片寬 ÷ 圖片比例
卡片高 = 圖片高 + 圖文間距 + 標題行數 × 行高 + 摘要高 + 卡片內距
區塊高 = 區塊標題列 + 各列最高的卡片加總 + 列間距
```

例:內容寬 1200px、3 欄、欄距 16px、3:2 → 卡片寬約 389px、圖高約 259px。

- **標題行數最容易估錯**,所以有兩種算法:
  - 規格公式 ⌈總寬 ÷ 欄寬⌉。
  - 逐字排入:中文一字一格,可以在任何位置換行;英文單字不能拆開。
- **字寬分三類**:全形 1 em、英數字約 0.55 em、半形標點與空白約 0.3 em。少了第三類,標題會多估一行,這是 POC 1 第一輪的教訓。
- 疊字型的標題前端會截成兩行,估算時也以兩行計,但另外回報「超出」。
- 左右並排的型(例如 P09),兩欄高度分開算,供「欄底對齊」使用。
- 計算全程保留小數,輸出時才四捨五入,保證每次結果相同。

POC 1 的實測:78 筆量測的區塊高度誤差最大 0.0%,標題行數 100% 正確(逐字排入)。

## 渲染:頁面 JSON → 一份 RWD 的 HTML

- 一份 HTML 對應所有寬度,只用 CSS media query 改排法,不依裝置輸出不同內容。
- 圖框用 `aspect-ratio`;範例資料沒有真圖,用比例正確的佔位框,並標示角色與比例。
- 每個區塊、標題、圖框都加上 data 屬性(實例 id、版位代號、圖片角色),方便量測找到它。
- 觸控目標(輪播箭頭、「更多」連結)至少 44×44px;不能有固定寬度造成水平捲動。
- 手機上依指定的順序,把側欄區塊移進單欄。

## 渲染量測:在 6 種寬度實際量

- 用 Playwright 驅動 Chromium,依序以 360、390、768、1024、1280、1440px 開啟頁面。
- 量測項目:每塊與每欄的高度、圖片實際顯示比例、同列卡片是否對齊、欄寬比例、觸控目標尺寸、是否水平捲動、每個標題的實際行數。
- 量到的數字與估算並列,作為校正公式和字型參數的依據。
- 為了每次結果相同:字型固定(Noto Sans TC)、deviceScaleFactor 固定為 1、輪播不自動播放。
- 每種寬度存一張整頁截圖,給人工與 AI 判讀。
