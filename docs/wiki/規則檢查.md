# 規則檢查(第 1 層)

> 白話說明 [`rule-check`](../../openspec/specs/rule-check/spec.md) 與 [`core-library`](../../openspec/specs/core-library/spec.md)。條文以 spec 為準。
>
> 狀態:✅ 第 1 階段已實作。

存檔時就跑的靜態檢查:不必渲染,看資料本身合不合法。結果分「錯誤」(不合法)與「警告」(合法但不建議)。

```bash
npm run validate
```

```bash
npm run validate -- --json --strict
```

- 有錯誤時結束代碼為 1;只有警告時為 0;加 `--strict` 時警告也算失敗。
- 參數錯誤時為 2。
- 同樣的資料一定得到同樣的結果,而且順序相同。

## 25 條規則,白話版

**資料本身**

| 代號 | 白話 |
| --- | --- |
| `schema` | 每份資料都要符合它那一種的格式(欄位、型別、可用的值) |
| `duplicate-id` | 同一種資料的 id 不能重複 |
| `ref-exists` | 引用到的東西要存在,例如範本引用的展示類型 |
| `single-site-profile` | 網站設定恰好一份 |
| `main-ratio-media-kind` | 平面站用 3:2、影視站用 16:9 |
| `pattern-limit` | 展示類型不超過 40 種 |
| `pattern-item-range` | 則數範圍的下限不能大於上限 |

**範本與實例**

| 代號 | 白話 |
| --- | --- |
| `template-item-count` | 範本的則數要在展示類型的範圍內 |
| `template-tabs` | 分頁籤型要寫分頁數,其他型不能寫 |
| `image-role` | 圖片角色要是展示類型允許的;有兩種可選時要選定;16:9 只給影音用 |
| `suggested-pattern` | ⚠️ 內容類型和展示類型不在建議搭配內(警告) |
| `override-fields` | 實例只能覆寫則數、選稿規則、區塊標題 |
| `override-item-count` | 覆寫後的則數仍要在範圍內 |
| `instance-item-count` | 實例實際放的則數要等於應有的則數 |
| `instance-content-match` | 放進去的新聞,內容類型與分類要和範本一致 |

**圖片**

| 代號 | 白話 |
| --- | --- |
| `item-crops` | 每則都要有主比例與 1:1 兩份;影音另外要有 16:9 |
| `image-file-ratio` | 圖檔比例和應有比例相差不超過 1% |
| `no-portrait` | 不能有直式圖 |
| `gallery-size` | 圖片牆的圖輯張數要在範圍內(P16 為 6~12 張) |

**頁面**

| 代號 | 白話 |
| --- | --- |
| `instance-on-one-page` | 每個實例恰好出現在一個頁面、一次 |
| `stack-columns-sum` | stack section 的欄寬加起來是 12 |
| `mobile-order-complete` | 指定的手機順序要剛好列出該 section 的所有區塊 |
| `code-capacity` | 版位代號用字母編,最多 26 個 |
| `device-hidden` | ⚠️ 在某類裝置整塊隱藏(警告) |
| `duplicate-item-on-page` | ⚠️ 同一則新聞在同一頁出現兩次(警告) |

## 幾個設計原則

- **格式錯的資料只報一次**:沒通過 `schema` 的資料不參加其他規則,但它的 id 仍算存在,避免一個錯誤引發一串誤報。
- **核心不碰執行環境**:檢查程式只吃 JSON、回傳結果,不讀檔、不連網,所以可以放進別的系統,或在瀏覽器裡執行。
- **測試資料可跨語言**:每條規則都有合法和不合法的 JSON 範例,用標準的 JSON Patch 描述「在基準資料上改哪裡」。日後移植到 Python 或 C#,可以直接沿用。
