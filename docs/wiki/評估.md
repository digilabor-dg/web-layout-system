# 評估

> 白話說明 [`template-evaluation`](../../openspec/specs/template-evaluation/spec.md)(第 2 層)、[`page-evaluation`](../../openspec/specs/page-evaluation/spec.md)(第 3 層)、[`evaluation-report`](../../openspec/specs/evaluation-report/spec.md)(判定、面向、報告)。條文以 spec 為準。
>
> 狀態:🧪 POC 2 已實作成 Lighthouse 式評估系統,做法與數字見 [評估系統](評估系統.md);正式版是第 2、4 階段。

## 分四層看

| 層 | 看什麼 | 什麼時候 | 結果 |
| --- | --- | --- | --- |
| 1 規則 | 資料合不合法 | 存檔時 | 合法 / 不合法(見 [規則檢查](規則檢查.md)) |
| 2 範本 | 每個區塊排出來好不好看 | 範本建立或修改時 | 合格 / 警告 / 不合格 |
| 3 頁面 | 整頁的順序、數量、層級、左右平衡 | 版面調整時 | 合格 / 警告 / 不合格 |
| 4 人工 | 整體感覺、是否刻意 | 上線前 | 意見 |

## 怎麼判

- 每個項目都有「一般標準」與「上限」:達一般標準算合格,介於兩者之間算警告,超過上限算不合格。
- 每個項目在 6 種寬度各判一次,**取最差的那次**。
- 任一項不合格,該範本或頁面就不合格;警告累積 3 項以上也視同不合格。

## 第 2 層:每個區塊

| 項目 | 白話 |
| --- | --- |
| 圖片比例 | 圖片實際顯示的比例要和應有比例差 1% 以內,沒有警告區間 |
| 同列對齊 | 同一列的卡片,圖片頂端和高度要對齊(差 1px 內) |
| 欄寬照格線 | 並排欄寬要照設定的比例(差 2% 內) |
| 欄底對齊 | 左右並排兩欄的底邊要齊(差 5% 內) |
| 末列不落單 | 網格最後一列不能只剩一兩則;餘數為 0 最好,至少要有欄數的一半 |
| 區塊長度 | 手機上一塊不要超過 1.5 個螢幕高 |
| 標題行數 | 電腦 2 行內、手機 3 行內;疊字標題最多 2 行 |
| 觸控目標 | 可以點的東西至少 44px |
| 水平捲動 | 不能出現 |
| 填充率 | 左圖右文時,右邊文字要佔圖高的 60%~90%,否則不是「右邊太空」就是「太擠」 |
| 列距 | 卡片與卡片的間距至少是卡片內圖文距的 2 倍,否則會「黏在一起」 |

## 第 3 層:整頁

| 項目 | 白話 |
| --- | --- |
| 手機首屏 | 手機第一個畫面裡,頭條圖不要佔超過 40% |
| 間距節奏 | 區塊之間的間距至少是區塊內則與則間距的 2 倍 |
| 同型不連續 | 相鄰的區塊不要用同一種展示類型;連續 3 塊就不合格 |
| 區塊數 | 首頁 10~15 塊最好,18 塊以上太長 |
| 整頁則數 | 30~80 則,超過 80 太多 |
| 單塊不重複 | 頭條、熱門排行、即時快訊各只能有一塊 |
| 放大型不相鄰 | 兩塊放大強調的型相鄰,會搶重點 |
| 用途則數 | 例如頭條 1 則、熱門排行 5~10 則 |
| 欄高 | 主欄與側欄的總高度差在 5% 內 |

「相鄰」在手機看單欄順序,在電腦看每一欄由上而下的順序,兩者取較差的結果。

**左右不平衡不一定是錯**:8:4 的主欄配側欄本來就左重右輕,比較的是「實際比例與設計比例的差距」。不平衡是不是編輯刻意的(例如加重頭條),由人或 AI 判斷,程式不自行認定。

## 8 個面向與分數

每個項目歸到一個面向,報告依面向彙整,讓人一眼看出缺點在哪一類、該往哪個方向改:

| 面向 | 涵蓋 | 常見改法 |
| --- | --- | --- |
| 比例 | 圖片比例 | 後端依主比例裁圖 |
| 對齊 | 同列對齊、欄寬、欄底、欄高 | 統一文字量、限制標題行數、換型 |
| 完整 | 末列不落單 | 則數調成欄數的倍數 |
| 密度 | 區塊長度、區塊數、則數、填充率 | 改輪播、加「看更多」、減則數 |
| 節奏 | 間距節奏、同型不連續、列距 | 換相鄰區塊的型、統一間距 |
| 層級 | 手機首屏、單塊不重複、放大型不相鄰 | 頭條改型、減少放大型 |
| 文字 | 標題行數 | 限字數、加寬欄 |
| 可用性 | 觸控目標、水平捲動 | 觸控 ≥ 44px、移除固定寬度 |

每個面向給 0~100 分,再加總平均。報告每頁、每種寬度一份,每一行寫出:量到的數字、判定、所屬面向、改進建議。
