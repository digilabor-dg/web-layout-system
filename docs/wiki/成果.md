## 第 1 階段:資料模型

- **schema**:9 種 prototype 的 JSON Schema(2020-12),外加共用定義與預設參數組的 schema。
- **範例資料**:
  - 範例站:平面、3:2、bs5、欄距 1rem。
  - 38 種展示類型,推定的屬性以 `inferred` 標記。
  - 7 種內容類型。
  - 首頁 A~M 共 13 個版位、61 則示意新聞。
- **第 1 層規則**:25 條,每條都有固定代號與嚴重度。`npm run validate` 支援 `--json`、`--strict`,結束代碼為 0、1 或 2。
- **跨語言設計**:
  - 核心不讀檔、不依賴 Node 專屬 API。
  - 測試寫成 JSON Patch 的 fixture,Python 或 C# 只要實作 add、remove、replace 三個操作就能沿用。
- **不寫死特定型**:分頁籤型看 `arrangement`、圖輯型看 `gallery`、16:9 縮圖看內容類型的 `requiresVideo`。換成電商或部落格,只要換資料。

## POC 1:JSON 估算 vs 實際渲染

範例首頁 13 塊 × 6 種寬度 = 78 筆量測(Chromium、Noto Sans TC)。

| 指標 | 結果 |
| --- | --- |
| 區塊高度誤差(修正後) | 中位數 0.0%,最大 0.0% |
| 區塊高度誤差(第一輪) | 最大 13.8%,原因是半形標點被當成英數字寬 |
| 標題行數正確率 | 逐字排入 100%;規格公式 ⌈總寬 ÷ 欄寬⌉ 99.2% |
| 換字型、估算參數不變 | 標題 99.7%,區塊最大誤差 6% |

**限制**:渲染器是照同一套盒模型寫的,所以這證明的是「公式與瀏覽器排版一致」,不是「能套用到任意網站的 CSS」。

## POC 2:評估系統

21 個項目(JSON 估算 16 項 + 渲染量測 5 項),8 個面向 0~100 分,一個項目只扣一次(同 Lighthouse)。範例首頁的結果:

| 總分 | 比例 | 對齊 | 完整 | 密度 | 節奏 | 層級 | 文字 | 可用性 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **74** | 100 | 40 | 70 | 80 | 70 | 90 | 70 | 70 |

21 個項目中,不合格 6、警告 3、合格 12。評估器抓到了 POC 1 截圖上肉眼看到的 4 個問題,也抓到肉眼漏掉的 3 個:疊字標題在 360px 會被截斷、平板推算造成末列落單、P09 左右兩欄不齊。詳見 [評估系統](評估系統.md)。

## POC 3:參數產生版型 + 表單

- **流程**:表單(`poc/generator/form.html`)→ 參數 JSON → 產生器挑每塊的展示類型、則數與排法 → 完整評估報表。
- **搜尋**:貪婪法或集束搜尋。每組參數約試算 350~420 種組合,只跑 JSON 估算時約 3 秒。
- **結果**:

  | 參數 | 完整評估總分 |
  | --- | --- |
  | default(bs5、貪婪法) | 90 |
  | tw4-beam(集束搜尋) | 90 |
  | no-sidebar(md3) | 96 |
  | from-form(表單產生) | 90 |

  手排首頁是 74 分。
- **⚠️ 評估器的漏洞會被搜尋利用**:`no-sidebar` 96 分,但觀點評論的方圖每張寬 1264px,整頁高 11,640px。電腦版沒有區塊長度的限制。產生器也偏好單調的 P07 均分圖卡。兩者都列在[待確認](待確認.md)。

## POC 5:skill + 人評對齊

- **skill**:`skills/layout-tuner`,產生 → 評分 → 判讀 → 調參數 → 重跑;短評由 skill 對應到評估項目。
- **檢視工具**:`poc/rating/review.html`,中間預覽、側欄工具(裝置切換、評分、A/B)。
- **8 個 AI 角色**(4 位專家、4 種讀者)第一輪:

  | 指標 | 結果 |
  | --- | --- |
  | A/B 一致率 | **57 / 75(76%)**;範例 07 是 0 / 8 |
  | 區塊評分與程式的等級相關 | −0.18 ~ 0.22 |
  | 盲點覆蓋率 | **10 / 33(30%)** |

- **最常見的盲點**:排行沒有名次、作者卡沒有作者(渲染器的 bug),以及電腦版區塊太長。

詳見 [人評對齊](人評對齊.md)。

## 評估器抓到的 bug 與限制

- **渲染器 bug**:「更多」連結寬度不足 44px(觸控目標),已修正。
- **型式限制**:P09 欄底對齊、P14 填充率、純文字側欄的欄高平衡,在規格允許的參數內無解。
- **平板推算偏保守**:「電腦欄數減一」讓 L 在 1024px 只有 2 欄。

詳見 [發現與型式限制](發現與型式限制.md)。
