# 評估系統

Lighthouse 式的版面評估:每個項目判定合格、警告或不合格,8 個面向各 0~100 分,附改善建議。程式在 [`poc/evaluate/`](../../poc/evaluate/README.md)。

```bash
npm run poc:2
```

```bash
npm run poc:2 -- 資料目錄 --json-only
```

## 流程

```
頁面 JSON ──┬─ JSON 估算(高度公式、標題行數)──── 16 個項目
            └─ 渲染(HTML)→ Chromium 6 種寬度量測 ─ 5 個項目
                                    │
              每個項目在 6 種寬度各判一次,取最差
                                    │
              8 個面向計分 → report.json / report.html
```

## 計分

- 每個面向 100 分起算,不合格扣 30、警告扣 10。
- **一個項目只扣一次**,以最差的對象為準;所有有問題的對象都列在明細裡。這和 Lighthouse 相同,分數不會因為區塊多就被放大。
- 總分是 8 個面向的平均。只跑 JSON 估算(`--json-only`)時,比例與可用性不給分。
- 整頁判定:任一項目不合格,或 3 個以上項目警告,即為不合格。
- 權重是經驗值,上線後用數據校正。

## 報表

| 檔案 | 給誰 | 內容 |
| --- | --- | --- |
| `report.json` | 程式、skill、日後的 MCP | 分數、整頁判定、每個項目 × 對象的判定;格式見 [`report.schema.json`](../../poc/evaluate/report.schema.json) |
| `report.html` | 人 | 分數圓環、改善建議、依面向列出的項目、截圖;手機也能閱讀,支援深色模式 |
| `REPORT.md` | 人(GitHub 上直接看) | 同內容的 Markdown |

每筆判定都有兩個識別:`target` 是給人看的版位代號(例如 H),`ref` 是穩定參照(實例 id)。區塊搬動後代號會重排,比對改善前後時用 `ref`。

## 確定性

同樣的輸入,`report.json` 逐字相同:

```bash
npm run poc:2 -- --check-determinism
```

渲染量測固定字型(Noto Sans TC)、deviceScaleFactor 1,輪播不自動播放。
